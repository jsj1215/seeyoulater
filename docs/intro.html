// why i built this

왜 만들었나

"나중에 봐야지" 하고 저장한 링크는 대부분 다시 열리지 않습니다. 저장하는 순간의 맥락이 남지 않기 때문입니다.

problem.txt

흩어진 저장소. 메신저 나에게 보내기, 브라우저 즐겨찾기, 메모 앱에 링크가 나뉘어 쌓여서 어디에 뒀는지부터 찾아야 합니다.

사라지는 맥락. URL만 남고 "누가 추천했는지, 왜 저장했는지, 얼마나 좋았는지"는 기억에서 빠집니다.

모바일에서 번거로운 저장. 휴대폰에서 본 링크를 정리된 곳에 넣으려면 복사, 앱 전환, 붙여넣기를 거쳐야 합니다.

solution.txt

한 곳에 저장, 메타데이터는 자동. URL을 붙여넣으면 서버가 OG 태그를 읽어 제목과 썸네일을 채웁니다.

맥락을 데이터로. 메모, 0~5 별점, 그리고 @로 시작하는 출처 태그로 "누구에게 받은 링크인지"를 남기고 From 화면에서 사람별로 모아 봅니다.

공유 시트에서 바로 저장. PWA Web Share Target으로 설치하면 다른 앱의 공유 메뉴에서 seeyoulater를 고를 수 있습니다.

// what it does

링크를 모으고, 정리하고, 발견합니다

단순 즐겨찾기가 아닙니다. 메타데이터 자동 수집부터 태그 필터, 캘린더 회고, 공개 폴더 발견까지 갖춘 지식 관리 도구입니다.

🔖

북마크 관리

URL만 넣으면 제목·썸네일·설명을 자동으로 가져옵니다(OG 메타데이터). 메모와 별점을 더하고, SSRF 방어로 안전하게 스크래핑합니다.

📁

폴더 정리

주제별 폴더를 만들고 드래그로 순서를 바꾸면 그 순서가 서버에 저장됩니다. 폴더마다 공개/비공개를 토글할 수 있습니다.

🏷️

태그 시스템

일반 태그(#해시태그)와 출처 태그(@사람)로 링크를 분류합니다. 어디서 알게 됐는지까지 추적됩니다.

🔍

검색 & 필터

제목·메모 키워드 검색에 폴더·다중 태그·날짜 필터를 조합합니다. 필터 조합은 JPA Specification으로 동적으로 만듭니다.

📅

캘린더 뷰

저장한 날짜 기준으로 북마크를 훑어봅니다. "그때 그 링크"를 시간으로 되짚을 수 있습니다.

🌐

Plaza 발견

다른 사람이 공개한 폴더를 둘러보고, 마음에 들면 내 계정으로 통째로 포크해 옵니다.

📊

통계 대시보드

총 링크 수, 폴더 수, 별표 항목을 레트로 상태 표시기로 한눈에 봅니다.

📱

PWA 지원

앱처럼 설치되고, Share Target API로 다른 앱에서 바로 공유받습니다. 모바일에서도 잘 동작합니다.

🔐

JWT 인증

httpOnly 쿠키 기반 JWT(SameSite=Lax, 7일 만료)로 로그인을 안전하게 처리합니다.

// design decisions

핵심 설계 결정과 트레이드오프

코드에 실제로 반영된 결정만 골랐습니다. 각 카드 하단에 근거가 되는 파일을 적어 두었습니다.

🔐 JWT를 httpOnly 쿠키에 담기

결정
로그인/가입 시 accessToken 쿠키(httpOnly, Secure, SameSite=Lax, 7일)로 내려주고, 필터가 쿠키에서 토큰을 꺼내 검증합니다. 인증이 없으면 401로 응답하고, 프론트는 401을 받으면 로그아웃 상태로 바꿔 로그인 화면으로 보냅니다.
이유
프론트엔드 JS가 토큰을 아예 만지지 않아 XSS로 토큰이 유출될 경로가 줄어듭니다. 새로고침 시에는 /api/auth/me 호출로 로그인 상태를 복원합니다.
트레이드오프
리프레시 토큰과 서버 측 토큰 폐기가 없어 로그아웃은 쿠키 삭제뿐입니다. CSRF 토큰은 끄고 SameSite=Lax에 기대고 있습니다. Safari는 http://localhost에서 Secure 쿠키를 저장하지 않아, 로컬에서 Safari로 개발할 때만 COOKIE_SECURE=false로 띄워야 합니다.
config/JwtAuthFilter.java · config/SecurityConfig.java · auth/AuthController.java · api/client.ts · store/authStore.ts

🛡️ OG 메타데이터는 서버에서, SSRF 방어와 함께

결정
브라우저 대신 백엔드가 Apache HttpClient 5로 대상 페이지를 받고, jsoup은 받은 바이트를 파싱하는 데만 씁니다. http/https와 80/443 포트만 허용합니다. 직접 구현한 DnsResolver가 DNS를 한 번만 조회해 나온 IP를 모두 검사하고, 검사를 통과한 그 IP로만 연결합니다. 리다이렉트는 최대 4번까지 직접 따라가며 홉마다 스킴, 포트, IP를 다시 확인합니다. 루프백, 사설 대역, link-local, 0.0.0.0/8, 100.64.0.0/10, 198.18.0.0/15, 멀티캐스트, fc00::/7, IPv4-mapped 주소가 차단 대상입니다.
이유
다른 사이트 HTML은 CORS 때문에 브라우저에서 읽을 수 없습니다. 서버가 대신 요청하는 순간 내부망 접근(SSRF) 통로가 됩니다. jsoup은 연결할 IP를 지정할 수 없어, 검증할 때와 연결할 때 DNS 응답이 달라지는 DNS 재바인딩을 막으려고 HTTP 클라이언트를 바꿨습니다. text/html만 파싱하고 본문 2MB, 전체 10초 제한을 두며, 실패하면 빈 메타데이터를 돌려줘 저장 자체는 막지 않습니다.
트레이드오프
의존성이 하나 늘었고, 공인 IP의 80/443 포트로 가는 요청은 그대로 허용됩니다. 외부에 공개된 다른 서비스로 요청을 대신 보내는 것까지 막지는 못합니다.
ogfetch/OgFetchService.java · ogfetch/OgFetchServiceTest.java · components/OgPreview.tsx (500ms 디바운스)

🔍 검색 조건은 JPA Specification으로 조합

결정
키워드, 태그 ID 목록, 폴더(-1은 미분류), 날짜, 별점 여부를 각각 Specification으로 만들고 값이 있는 것만 AND로 묶습니다. 키워드의 %, _는 이스케이프해 글자 그대로 찾고, lower(col) LIKE 형태에 맞춰 init.sql에 lower(title), lower(memo) pg_trgm 표현식 인덱스를 두었습니다.
이유
선택 필터가 5개라 메서드 이름 쿼리로는 조합이 폭발합니다. 같은 조각을 폴더별 개수, 캘린더 날짜 조회, 공개 폴더 조회, 포크에서도 재사용합니다.
트레이드오프
태그 필터는 OR(IN) + distinct입니다. 폴더 목록은 폴더마다 count 쿼리를 따로 보내 폴더 수만큼 쿼리가 나갑니다. 테스트는 H2에서 돌아서 pg_trgm 인덱스를 실제로 타는지는 테스트로 확인하지 않습니다.
bookmark/BookmarkSpec.java · bookmark/BookmarkService.java · init.sql

🗄️ 스키마는 SQL이 소유, Hibernate는 검증만

결정
테이블은 init.sql이 만들고(docker-compose가 최초 기동 시 실행), 애플리케이션은 ddl-auto: validate로 엔티티와 스키마가 맞는지만 확인합니다.
이유
pg_trgm 확장, GIN 인덱스, 별점 CHECK(0~5), 폴더 삭제 시 ON DELETE SET NULL, 태그 연결 CASCADE처럼 Hibernate DDL로 표현하기 어려운 제약을 DB에 직접 둡니다. 엔티티가 어긋나면 기동 시점에 바로 실패합니다.
트레이드오프
Flyway 같은 마이그레이션 도구가 없어 스키마 변경은 수동 SQL입니다. init.sql은 빈 볼륨에서만 자동 실행되므로, 파일 전체를 여러 번 실행해도 안전하게 작성해 두고 기존 DB에는 직접 한 번 더 실행합니다.
init.sql · application.yml · docker-compose.yml

🏷️ 출처는 별도 테이블 대신 "@ 태그" 규칙

결정
"누구에게 받은 링크인지"를 위한 테이블을 따로 두지 않고, 이름이 @로 시작하는 태그를 출처로 취급합니다. 태그는 사용자별로 유일(UNIQUE(user_id, name))하고 저장 시 없으면 만듭니다.
이유
출처도 결국 링크를 묶는 라벨이라 태그 검색, 필터, 이름 변경 기능을 그대로 쓸 수 있습니다. From 화면과 태그 관리 화면은 접두어로만 두 종류를 나눕니다.
트레이드오프
구분이 스키마가 아닌 이름 규칙에 있어서 DB 차원의 강제가 없습니다. 사람별 프로필 같은 속성을 붙이려면 그때 테이블로 분리해야 합니다.

📲 공유 시트 → 로그인 → 저장 흐름 보존

결정
PWA manifest의 share_target이 /share?url=&title=로 들어오면, 로그인 상태면 바로 추가 화면으로 넘기고 아니면 URL을 sessionStorage에 넣어 두었다가 로그인 후 추가 화면에서 꺼냅니다.
이유
공유 시트로 들어온 순간 세션이 만료돼 있어도 링크를 잃지 않게 하려는 것입니다. 일부 앱은 URL을 text로 넘기므로 url이 없으면 text를 씁니다.
트레이드오프
sessionStorage라 탭을 닫으면 대기 중인 링크가 사라집니다. 서비스 워커는 정적 자산만 캐시하고 /api 응답은 개인 데이터라 캐시하지 않으므로 오프라인에서는 조회도 저장도 되지 않습니다. 로그아웃하면 Cache Storage를 비웁니다.

데이터 모델과 API

모든 데이터는 user_id로 사용자에게 묶여 있고, /api/public/**와 가입, 로그인, 로그아웃만 로그인 없이 열려 있습니다. 남의 리소스 id로 요청하면 없는 id와 똑같이 404가 돌아옵니다.

users

id · email UNIQUE · password(BCrypt) · created_at

folders

id · user_id → users · name · is_public · sort_order · UNIQUE(user_id, name)

bookmarks

id · user_id → users · folder_id → folders ON DELETE SET NULL · url(2048) · title · thumbnail_url · memo · rating CHECK 0~5 · created_at · updated_at

tags

id · user_id → users · name · sort_order · UNIQUE(user_id, name)

bookmark_tags

(bookmark_id, tag_id) PK · 양쪽 ON DELETE CASCADE

인덱스

bookmarks(user_id, created_at DESC) · bookmarks(folder_id) · GIN(lower(title)), GIN(lower(memo)) gin_trgm_ops · bookmark_tags(tag_id)

보안 설계

applied.log
  • 비밀번호는 BCrypt로 해시합니다. BCrypt가 72바이트 뒤를 무시하는 문제(CVE-2025-22228) 때문에 8~72자 제한에 더해 UTF-8 바이트 수도 검사합니다.
  • 로그인 실패는 이메일 존재 여부와 상관없이 같은 401 메시지입니다. 없는 이메일이어도 더미 해시와 한 번 비교해 응답 시간으로 가입 여부를 짐작하기 어렵게 했고, 중복 가입도 일반 메시지와 함께 409로 응답합니다.
  • 소유권 검사: 북마크, 폴더, 태그 모두 findByIdAndUserId로 조회해 남의 리소스는 없는 id와 같은 404를 돌려줍니다.
  • 쿠키는 httpOnly, Secure, SameSite=Lax입니다. 인증이 없으면 401로 응답합니다.
  • 입력 검증: URL과 썸네일은 http(s)만 2048자까지, 메모 10000자, 북마크당 태그 30개, 태그명 100자(북마크 저장 시 태그 이름에도 적용), 폴더명 200자, 페이지 크기 100.
  • SSRF 방어: 검증한 IP로만 연결(DNS 재바인딩 방지), 리다이렉트마다 재검증, 80/443 포트만, 내부망과 특수 대역 차단, text/html만 파싱, 2MB와 10초 제한.
  • Rate limit: 로그인 분당 10회, 가입 분당 5회, OG 조회 분당 30회(IP별). 넘으면 429와 Retry-After.
  • 공개 API는 이메일 대신 마스킹한 이름만, 북마크는 url, 제목, 썸네일, 저장일만 내보냅니다. 포크도 같은 범위만 복사합니다.
  • 시크릿 분리: JWT 키와 DB 접속 정보는 환경변수로 받습니다. JWT_SECRET은 기본값이 없어 설정하지 않으면 서버가 뜨지 않습니다. 로컬에서는 gitignore된 backend/.env를 Spring이 자동으로 읽습니다. DB 포트는 127.0.0.1에만 열립니다.
  • CORS는 CORS_ALLOWED_ORIGINS(기본 http://localhost:5173)에 적힌 출처만 credentials와 함께 허용하고, 보안 필터 체인 맨 앞에서 처리합니다.
  • 프론트엔드: 로그아웃 시 Cache Storage 삭제, 외부 이미지는 no-referrer, 파비콘은 사이트 자체 /favicon.ico만 요청합니다.
todo.log
  • Rate limit은 서버 메모리에 있어 인스턴스 한 대일 때만 정확합니다. 프록시 뒤에 두려면 forward-headers 설정이 필요합니다.
  • 토큰 폐기 목록이 없어 발급된 JWT는 7일 동안 유효합니다.
  • 마스킹된 이름에도 이메일 로컬파트 앞 2자가 보입니다.
  • 공개 폴더 목록은 페이징이 없고, 폴더마다 count 쿼리가 따로 나갑니다(N+1).
  • OG 수집은 공인 IP의 80/443 포트로 가는 요청을 허용합니다.

실행 방법

JDK 17 또는 21, Node.js 20.19 이상, Docker가 필요합니다. 자세한 내용은 README를 참고하세요.

Terminal — seeyoulater
# 1. PostgreSQL 기동 (init.sql로 스키마 자동 생성) $ docker compose up -d # 2. 백엔드 환경변수: JWT_SECRET 채우기 (openssl rand -base64 48) $ cp backend/.env.example backend/.env # (기존 DB라면) 스키마 변경 반영: init.sql 다시 실행 $ docker compose exec -T postgres psql -U seeyoulater -d seeyoulater -v ON_ERROR_STOP=1 < init.sql # 3. 백엔드 실행 → http://localhost:8080 $ cd backend && ./gradlew bootRun # 4. 프론트엔드 실행 → http://localhost:5173 $ cd frontend && npm install && npm run dev # 백엔드 테스트 (H2, JDK 17 또는 21) $ cd backend && ./gradlew test

테스트: 백엔드 테스트 69개(AuthApiTest 10, ResourceApiTest 12, OgFetchServiceTest 47)가 H2의 PostgreSQL 호환 모드에서 돌아서 Docker 없이 실행됩니다. Gradle 8.7 wrapper는 JDK 24에서 동작하지 않으니 JDK 17이나 21로 실행하세요. 프론트엔드는 npm run lint와 타입 체크를 포함한 npm run build로 검증합니다.
